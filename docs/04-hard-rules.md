# 04. P0 硬性規則

P0 是硬性規則：**任何一條不成立，就不是合法班表**。P0 不可關閉、不可調整順序。
嚴格候選與 Published 必須全部通過；Draft 可暫存違規但不得發布。

P0 適用**整個排班區間**（含延伸排班日），並須銜接歷史（跨月檢查）。

## 1. 共通硬規則

### GEN-H-01 每日唯一

每人每個排班日期只能有一個狀態（早／午／夜／跨站班／R／R\*／X 其中之一）。
X 的**開始日期**不得同時排早／午／夜／R／R\*。

- 跨午夜 X 的結束日期不受此限制，可照常排班（決策 D-01）。
- 事件彼此衝突不是交給求解器選擇，而是 `INVALID_INPUT`（見 `03` 第 6 節）。

### GEN-H-02 最多連續 6 日

任何**連續 7 個曆日**中，工作日數不得超過 6。早／午／夜／X 都算工作日。

- 國定假日不會自動中斷連續工作；只有 R／R\* 是休假。
- 檢查窗涵蓋歷史：例如歷史最後 6 天連續工作，本月 1 日就不得再排工作。

### GEN-H-03 休息至少 11 小時

前一次**實際工作結束時刻**到下一次**實際工作開始時刻**，至少 11 小時。
正常班與 X 都使用完整日期時間計算；月初第一筆工作以歷史的「上一次實際工作結束時間」檢查。

例：M 午班 22:20 結束，隔日早班 06:30 開始，只有 8 小時 10 分 → 禁止。

### GEN-H-04 8 週 R

每個 ScheduleCycle 有 `start`、`end`、`requiredR`（由管理者維護，所有 M、T 共用；
例如 `requiredR` 可為 16 加該週期認定的國定假日數）。

對每個與「歷史範圍＋排班區間」相交的週期 C，令 `R_total(C)` ＝ 該人在 C 內的
R 天數＋已滿足 R\* 天數（含 Published 歷史與本次排班結果）：

- 若 C 的結束日 ≤ 排班區間最後一天（週期在本次區間內結束）：
  到 C 結束日為止，`R_total(C)` 必須**剛好等於** `requiredR`。
- 若 C 的結束日 > 排班區間最後一天（週期尚未結束）：
  1. `R_total(C)` 不得超過 `requiredR`；
  2. 剩餘可排日數必須足以補足：`requiredR − R_total(C)` ≤ C 內位於排班區間之後的天數。

### GEN-H-05 歷史與固定事件

Published 歷史、已發布的延伸排班日、以及 X 事件，**不得由求解器改寫**。
新 R\*／X 若與已發布日期衝突，須先走人工版本流程（重新發布新版本），不能默默覆蓋
（輸入階段即擋下，`INVALID_INPUT`）。

## 2. M 單位硬規則

### M-H-01 只能在本站或同群組車站工作

M 只能在 `homeStation` 或同群組車站工作。群組：A＝LB01–03、B＝LB04–06、
C＝LB07–09、D＝LB10–12。**跨群組選項不存在**（模型中不建立該變數）。

### M-H-02 嚴格候選每個班位必須補足

排班區間內每個 M 班位（每站每日早 1、午 1；LB01／LB06／LB08／LB12 另夜 1）：
**內部指派＋合法外派＝需求**。UNASSIGNED 只可出現在缺班分析。

### M-H-03 只有 LB02、LB04、LB11 可使用外派

外派只記錄班位（Coverage 的 `external` 欄），不建立假員工列。
C 群組（LB07–09）沒有可外派車站；其人力不足時嚴格模型即無解（業務確認正確，決策 D-02）。

## 3. T 單位硬規則

### T-H-01 T 的正常工作只能是該日期的固定班別

- 目標月內：依 `EmployeeMonthlyShift`（當月班組）。
- 延伸到下月的日期：有明確下月班組資料以資料為準，否則依「早→午→夜→早」輪轉推算。
- 此規則只限制**正常班**；R／R\*／X 不受班別限制。

## 4. 發布前必須通過（發布檢查清單）

1. 所有 P0（GEN-H-01～05、M-H-01～03 或 T-H-01）。
2. M：不得有缺班（每個班位補足）或非法外派（非 LB02／LB04／LB11）。
3. T：不得被排到非當日固定班別的正常班。
4. 所有必要歷史、8 週週期、班別時間與人員資料均完整。

任何一項不過，發布功能停用並列出白話原因（見 `08-frontend.md`）。
