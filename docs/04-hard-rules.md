# 04. P0 硬性規則

P0 是硬性規則：**任何一條不成立，就不是合法班表**。P0 不可關閉、不可調整順序。
嚴格候選與 Published 必須全部通過；Draft 可暫存違規但不得發布。

P0 適用**整個排班區間**（含延伸排班日），並須銜接歷史（跨月檢查）。

## 1. 共通硬規則

### GEN-H-01 每日唯一

每人每個排班日期只能有一個狀態（早／午／夜／跨站班／R／R\*／R1／X 其中之一）。
X 的**開始日期**不得同時排早／午／夜／R／R\*／R1。

- 跨午夜 X 的結束日期不受此限制，可照常排班（決策 D-01）。
- 事件彼此衝突不是交給求解器選擇，而是 `INVALID_INPUT`（見 `03` 第 6 節）。

### GEN-H-02 最多連續工作 6 日（R1 不重置計數）

**定義**：在任意兩個 R 或 R\* 之間（不含端點），實際工作日（早／午／夜／X）數不得超過 6。

各狀態對本規則的效果：

- 早／午／夜／X：算工作日，計數加 1。
- R、已滿足的 R\*：不算工作日，且**重置**連續工作計數（唯二的重置點）。
- **R1：不算工作日，但不重置計數**——計數跨過 R1 繼續累計。
- 國定假日「當天」本身不影響計數；只看該日排的狀態。

等價的逐日演算法（evaluator 與求解器都必須用這個語意，見下方「常見錯誤」）：

```text
cw(d) = 0             若 d 為 R 或 R*
cw(d) = cw(d−1)       若 d 為 R1
cw(d) = cw(d−1) + 1   若 d 為 早/午/夜/X
限制：對每一天 cw(d) ≤ 6
```

月初以歷史接續計算（歷史中的 R1 同樣不重置）。

例 1：`早, 早, 早, R1, 午, 午, 午` → 實際工作日共 6；R1 不算工作日、也沒有切斷計數
（cw 序列 = 1,2,3,3,4,5,6）。**下一日不可再排早／午／夜／X，必須排 R 或 R\*。**

例 2：歷史最後 6 天連續工作（其間無 R／R\*）→ 本月 1 日不得排工作日。

**常見錯誤描述（皆不正確，不得寫入程式或文件）**：

- 「所有休假都會切斷連續工作」——錯，R1 是休假但不切斷。
- 「所有非工作日都會切斷連續工作」——錯，R1 非工作日但不切斷。
- 「R1 與 R 的效果完全相同」——錯，唯一差異就在本規則。
- 「只需檢查任意固定 7 日視窗內工作日 ≤ 6」——錯，R1 會把工作區間拉長超過 7 個曆日
  （例 1 加下一日共 8 個曆日），固定視窗會漏抓違規；必須用上述計數語意。

### GEN-H-03 休息至少 11 小時

前一次**實際工作結束時刻**到下一次**實際工作開始時刻**，至少 11 小時。
正常班與 X 都使用完整日期時間計算；月初第一筆工作以歷史的「上一次實際工作結束時間」檢查。

例：M 午班 22:20 結束，隔日早班 06:30 開始，只有 8 小時 10 分 → 禁止。

### GEN-H-04 8 週休假數量（一般休假與 R1 分開計）

每個 ScheduleCycle 有 `start`、`end`、`requiredR`（**一般休假需求，預設 16**）、
`requiredR1`（**該週期認定的國定假日數**）。由管理者維護，所有 M、T 共用同一份週期表。

**兩個額度必須分開限制，不得合併**成「全部休假 = requiredR + requiredR1」單一條件——
因為 R1 與 R／R\* 對 GEN-H-02 的效果不同，合併計數會讓求解器把 R 換成 R1（或反之）
而破壞連續工作規則的語意。

對每位人員、每個與「歷史範圍＋排班區間」相交的週期 C，定義（皆含 Published 歷史）：

- `Rgen(C, t)` ＝ C 內日期 ≤ t 的 R 天數＋已滿足 R\* 天數（一般休假）。
- `R1(C, t)` ＝ C 內日期 ≤ t 的 R1 天數。
- `cycleDays` ＝ C 的總天數（8 週 = 56）。

**(a) 週期在排班區間內結束**（C.end ≤ 排班區間最後一天）——到 C.end 為止必須：

1. `Rgen(C, C.end) == requiredR`（**剛好**等於，預設 16）；
2. `R1(C, C.end) == requiredR1`（**剛好**等於；R1 可排在 C 內任意日期，不必在國定假日當天）。

**(b) 週期尚未結束**（C.end > 排班區間最後一天）——令 t ＝ 排班區間最後一天：

1. `Rgen(C, t) ≤ requiredR` 且 `R1(C, t) ≤ requiredR1`；
2. 剩餘日數足以補足兩者：
   `(requiredR − Rgen(C, t)) + (requiredR1 − R1(C, t)) ≤ C 內位於 t 之後的天數`。

**(c) 跨月比例保留一般休假（決策 D-19；只適用 R／R\*，R1 不納入此公式）**：

若 C.end > 目標月最後一日（`monthEnd`），另加下列限制：

```text
futureDays          = C 內日期 > monthEnd 的天數
reservedGeneralRest = ceil(requiredR × futureDays / cycleDays)
限制：Rgen(C, monthEnd) ≤ requiredR − reservedGeneralRest
```

目的：把 requiredR（16）個一般休假按週期剩餘日數比例分配，替同週期的下一個月保留 R，
不得在本月把額度用光。

- 累計**只算日期 ≤ monthEnd** 的 R／R\*；**排在延伸日（> monthEnd）的 R／R\* 不消耗本月上限**
  ——延伸日屬於 `futureDays`，其休假發布後於下次排班計入。
- 若 C.end ≤ monthEnd（目標月已涵蓋週期最後一天）：不使用比例保留，直接套 (a) 的兩個等式。
- 若 monthEnd < C.end ≤ 排班區間最後一天（週期在延伸日內結束）：(a) 與 (c) 同時適用。
- R1 只需滿足 (a)／(b)，**沒有**比例保留限制。

**數字例**：週期 56 日、requiredR = 16、該週期有 2 個國定假日（requiredR1 = 2）。

- 目標月月底後，週期仍剩 `futureDays = 14` 日 →
  `reservedGeneralRest = ceil(16 × 14 / 56) = 4` → 截至月底 `Rgen ≤ 16 − 4 = 12`，
  也就是月底後至少必須保留 4 個 R 或 R\*。
- 完整週期結束時：R＋R\* 恰為 16、R1 恰為 2，非工作日合計 18。

### GEN-H-05 歷史與固定事件

Published 歷史、已發布的延伸排班日、以及 X 事件，**不得由求解器改寫**。
新 R\*／X 若與已發布日期衝突，須先走人工版本流程（重新發布新版本），不能默默覆蓋
（輸入階段即擋下，`INVALID_INPUT`）。

## 2. M 單位硬規則

### M-H-01 只能在本站或同群組車站工作

M 只能在 `homeStation` 或同群組車站工作。群組：A＝LB01–03、B＝LB04–06、
C＝LB07–09、D＝LB10–12。**跨群組選項不存在**（模型中不建立該變數）。

### M-H-02 嚴格候選每個班位必須補足

排班區間內每個 M 班位（每站每日早 1、午 1；LB01／LB06／LB08／LB12 另夜 1）：
**內部指派＋合法外派＝需求**。UNASSIGNED 只可出現在缺班分析。
只有正常班（含跨站支援）能補班位；R、R\*、R1、X 都**不算**班位覆蓋。

### M-H-03 只有 LB02、LB04、LB11 可使用外派

外派只記錄班位（Coverage 的 `external` 欄），不建立假員工列。
C 群組（LB07–09）沒有可外派車站；其人力不足時嚴格模型即無解（業務確認正確，決策 D-02）。

## 3. T 單位硬規則

### T-H-01 T 的正常工作只能是該日期的固定班別

- 目標月內：依 `EmployeeMonthlyShift`（當月班組）。
- 延伸到下月的日期：有明確下月班組資料以資料為準，否則依「早→午→夜→早」輪轉推算。
- 此規則只限制**正常班**；R／R\*／R1／X 不受班別限制。

## 4. 發布前必須通過（發布檢查清單）

1. 所有 P0（GEN-H-01～05、M-H-01～03 或 T-H-01）。
2. M：不得有缺班（每個班位補足）或非法外派（非 LB02／LB04／LB11）。
3. T：不得被排到非當日固定班別的正常班。
4. 所有必要歷史、8 週週期、班別時間與人員資料均完整。

任何一項不過，發布功能停用並列出白話原因（見 `08-frontend.md`）。
