# 資料格式與驗證

## 日期文字格式

所有使用者可見、匯入與匯出的日期文字統一使用零補齊的 ISO 形式：完整日期為 `yyyy-MM-dd`、月份為 `yyyy-MM`；若只顯示月日則為 `MM-dd`。分隔符號一律使用半形連字號 `-`，不接受 `2026/8/7`、`2026-8-7` 或其他地區格式。時間使用 `HH:mm`。

## Solver 入口

Solver 不讀 CSV、Excel、DB 或 UI，只接受 typed snapshot：

```csharp
public sealed record ScheduleInput(
    MonthlySchedule PreviousMonth,
    MonthlySchedule DemandMonth,
    IReadOnlyList<RestInterval> RestIntervals);
```

`DemandMonth` 是本月人員資料的唯一來源，不另建員工主檔。上月有、本月沒有的人不排入本月。

## 月班表 CSV

欄位順序固定：

```text
ID,姓名,所屬,到職日期,能力,T月班別,
月初區間累計R,月初區間累計R1,
1,...,31,
當月R,當月R1,當月指定R休,月底區間累計R,月底區間累計R1,本月班數
```

- M：所屬填車站；能力、T 月班別留空。
- T：所屬填專業分組；能力填 1–5；T 月班別填早、午或夜。
- 既有人員的到職日期可留空，代表在目標月以前已到職；有填寫時使用 `yyyy-MM-dd`。
- 當月不存在的 29–31 號與到職日前必須留空。
- CLI 支援 UTF-8 BOM 與 RFC 式 quoted field；本版不直接讀寫 `.xlsx`。
- `月初區間累計R/R1` 是本月 1 日開始前，在月初所屬 56 日區間內已計入的 R/R1。
- `當月R/R1` 由 1–31 日日格自動計算。歷史與候選列必須填寫且與日格一致；需求列連同月底區間累計欄留空。
- `月底區間累計R/R1` 是截至本月最後一日，在月底所屬 56 日區間內已計入的 R/R1。
- `當月指定R休` 在需求月表示精確需求數，空白視為 0，否則必須是非負整數；歷史與候選則填由日格重算的實際 R休數。

日格可用：空白、`R`、`R1`、歷史用的 `R休`、`R*`、`R*[R]`、`R*[R1]`、`R*[R休]`、`X[08:30-17:30]`、M 的 `LB01早`（也接受簡寫 `1早`；站號為 1–12）、T 的 `早`。需求月不得直接填未標示 R* 的 `R休`。M 午班輸入同時接受 `LB01小`／`1小` 與舊稱 `LB01午`／`1午`，輸出一律正規化為 `LB01小`；T 午班仍使用 `午`。

X 的結束時間小於或等於開始時間時，視為隔日結束；時長不得超過 24 小時。

## 八週區間 CSV

```text
區間開始日期,區間結束日期,國定假日日期
2026-07-20,2026-09-13,2026-08-14
2026-09-14,2026-11-08,2026-09-18;2026-10-12
```

每區間必須剛好 56 日；相鄰區間必須連續、不重疊、無缺口。國定假日必須在所屬區間內且為週一至週五。Solver 建模範圍內的每天必須剛好落在一個區間。

## 歷史、新進與累積

- 既有人員必須在上月班表有整月已決定歷史，並提供上月底 R/R1 累積與正常班次數。
- 到職日期留空者視為既有人員，仍須提供上月班表；沒有上月歷史者必須填寫落在本月內的到職日期。
- 本月有、上月沒有，且到職日在本月內，視為新進。
- 到職日早於本月卻無上月歷史，為 `InvalidInput`。
- 新進人員在到職日前，以區間內已經過的六、日數當作已計 R，已經過的國定假日數當作已計 R1。
- 月中到職者不參與整月公平性比較，但到職後仍適用每日規則與個人月目標。

## 輸入錯誤

Solver 不丟出業務驗證例外；回傳 `SolveStatus.InvalidInput` 與 `InputError(Field, Message)`。主要錯誤包含：

- 月份不連續、重複 ID、必要欄位缺失。
- 同一員工的上月與本月到職日期不一致，包括一邊空白、一邊有值。
- M/T 欄位混用，T 能力或月班別無效。
- 歷史日格缺失、仍為未決定 R*、或固定工作間隔不足 11 小時。
- 指定 R休數為負數、小於固定 `R*[R休]` 數、超過可決定的 R* 數，或需求月直接固定未標示 R* 的 R休。
- 日格在月份外、到職日前非空白、X 時間或班別不合法。
- 八週區間天數、連續性、假日日期或覆蓋範圍錯誤。
