# 09. 最低驗收案例

每個案例應有對應的自動化測試（單元或整合）。AC-01～AC-10 來自原規格書；
AC-11 之後為釐清決策新增的邊界案例。

| ID | 案例 | 預期結果 |
|---|---|---|
| AC-01 | 目標月月底為星期三 | 排班區間延伸到該週星期日；延伸日納入 P0 與班位需求，但完全不計本月統計與任何軟規則分數 |
| AC-02 | 序列 `早, X, 午, R, 夜` | 連續工作區段長度為 3 與 1 |
| AC-03 | 序列 `早, R, 早, X, 早, 午` | M 同班別區塊為「早 3 次」與「午 1 次」 |
| AC-04 | M 午班 22:20 結束後，隔日排早班 06:30 | GEN-H-03 禁止（僅 8 小時 10 分） |
| AC-05 | M LB01 人員排 LB03；排 LB04 | 前者為合法同群組支援；後者跨群組，模型中不存在此選項 |
| AC-06 | T 班組 11 人、某日正常出勤 4 人 | 目標 `floor(11/2)=5`，T-S-ATTEND 違反量加 1 |
| AC-07 | T 某班出勤能力 2、3、3、3 | 總和 11、需求 12，T-S-ABILITY 違反量為 1 |
| AC-08 | 只能找到 2 份差異候選 | `candidateCount=2`，`scheduleStatus` 仍為 `FEASIBLE` |
| AC-09 | Draft 人工修改造成缺班 | 允許暫存、立即標示違規、發布功能停用並列出原因 |
| AC-10 | M 嚴格模型無解 | 回傳 `INFEASIBLE`，另有不可發布的 ShortageAnalysis（僅放寬班位覆蓋、最小化缺額） |
| AC-11 | X 跨午夜（如 8/15 21:00–8/16 05:00） | 8/15 顯示 X、算 1 個工作日；8/16 由求解器決定；8/16 若排正常班須距 05:00 至少 11 小時（M 夜 22:00 可、T 早 07:00 不可） |
| AC-12 | 同一人同日同時有 R\* 與 X | `INVALID_INPUT`，訊息指出人與日期 |
| AC-13 | 某人某週期 R\* 數量＋歷史 R 已超過 requiredR | `INVALID_INPUT`，訊息指出員工與週期（不進求解器） |
| AC-14 | 新 R\* 落在已發布的日期上 | `INVALID_INPUT`，提示需走人工版本流程 |
| AC-15 | 週期在排班區間內結束 | 該週期結束日時 R＋已滿足 R\* 剛好等於 requiredR，否則無解 |
| AC-16 | 週期橫跨區間尾端 | 累積 R 不超過 requiredR，且剩餘天數足以補足，否則無解 |
| AC-17 | 排班區間橫跨兩個 8 週週期 | 公平性規則對兩個週期分別計算 max−min 後相加 |
| AC-18 | 歷史最後 6 天連續工作 | 本月 1 日不得排工作日（GEN-H-02 跨月檢查） |
| AC-19 | 歷史不足 8 週或缺 events.csv | `INVALID_INPUT`，回報資料不足，不自行猜測 |
| AC-20 | R\* 未滿足 | 該格顯示實際班別；violations 含 `GEN-R-01` 紀錄；候選比較顯示未滿足數 |
| AC-21 | 前月夜班組、本月早班組，中間只有 1 個 R | T-S-MONTH-REST 違反量加 1 |
| AC-22 | 某規則求解逾時但已有合法解 | 保留目前最佳解、標示 `TIME_LIMIT`、不處理更低順位規則、不宣稱該規則最佳 |
| AC-23 | 系統重啟時有 Queued／Running 的 ScheduleRun | 依快照重新開始執行，結果狀態正確 |
| AC-24 | 重新發布同單位同月 | 建立新版本，舊版本唯讀可查，「目前 Published」只有一份 |
| AC-25 | 工作區段跨過月底、在延伸日內結束（如 8/30 起連續工作至 9/1，9/2 為 R） | 本次不評分該區段（視為未結束尾端），保存至 8/31 的長度 2；下次排班承接後評分完整長度 |

## 完成定義（Definition of Done）

- 未參與需求討論的開發者可只依本組文件理解名詞、規則、跨月邊界及系統責任。
- M、T 全部 P0、延伸排班日、跨月歷史與 8 週週期測試通過。
- 每條 P2–P4 規則可獨立開關、排序，並輸出 Rule ID、目前指標與白話 Violation。
- 互動寬表可修改 Draft，立即顯示 P0、Coverage、T 能力／專業及發布阻擋原因。
- 嚴格候選、TIME_LIMIT、INFEASIBLE、ShortageAnalysis、Draft 與 Published 不混淆。
- 實作遇到文件未定義的業務情況時，回報規格缺口，不自行補上業務假設。
