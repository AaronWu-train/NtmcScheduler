# 08. 前端功能與互動寬表

本文件定義第一版 Blazor Interactive Server UI。Blazor 元件不直接建立 OR-Tools 模型；所有寫入、驗證與求解均呼叫後端 application service。UI 文字一律繁體中文，不建立 S 空殼或額外儀表板。

流程為：Demand 草稿 → 背景求解 → 候選版本 → 人工修改 → `★` 採用版本；無審核／發布狀態機。

## 1. 路由頁面

### 共同頁面

- 登入／修改密碼：無註冊與忘記密碼；首次登入或管理者重設後強制修改一次性密碼。
- 工作區入口：只呈現 M、T 及目前使用者可執行的操作。
- 共同設定：編輯連續 56 日／16 R 區間、區間內國定假日及非常態班型；兩區塊各自提供固定格式 CSV 與「儲存設定」，前端不顯示內部版本資訊。系統仍以不可變快照保留舊 Demand 與班表所使用的設定。
- 帳號與權限：只限 Administrator 建立、停用、重設密碼及配置 M/T 編輯權。
- 稽核紀錄：只限 Administrator 依日期、工作區與動作查詢；畫面不提供修改或刪除。

### M／T 工作區

- 員工列表：M 為 ID、姓名、所屬車站、到職日期；T 為 ID、姓名、專業分組、到職日期、能力 1–5。可表格新增／修改／刪除，也可用固定表頭 CSV 預覽後匯入。刪除前須確認；刪除後可用相同 ID 重新建立回任人員，既有 Demand／班表快照不變，刪除前內容保存在 AuditLog。
- Demand／排班：下拉選單列出該工作區已建立的月份並在選取後直接開啟；選「新增月份…」才顯示月份欄位並建立唯一草稿。頁面依月份、上月班表、本月需求、M 萬年班表（僅 M）與求解分步顯示。Demand 可刪除及同月份重建，既有求解紀錄、候選班表與採用班表不受影響。
- 已排班表：第一層依月份顯示版本數與 `★`；月份內列出候選狀態、時間、警示與封存狀態，可開啟、標星、封存及下載 CSV；M 有外派資料時另提供 external CSV。
- 班表編輯器：一人一列，完整沿用 CLI 月班表固定欄位、順序與內容，支援雙向捲動及逐格編輯。

## 2. 寬表日格與統計

- M 正常班顯示早／小／夜並指定 LB01–LB12 站別；T 顯示早／午／夜。
- 可選 R、R1、R休、`R*`、`R1*`、`R休*`、正常班與 X。Demand 的 `R*` 可保持未決定；班表中的星號休假保存為 requested-rest 加實際類型。
- X 可套用共同設定班型，或輸入台北時間開始、結束與說明；可跨午夜但最長 24 小時，歸開始日期。
- 每格修改立即保存；整份班表使用 GUID revision token 做樂觀鎖定，衝突時拒絕覆寫並要求重新整理。
- Demand 與班表編輯器的寬表表頭固定與 CLI 月班表完全相同：`ID、姓名、所屬、到職日期、能力、T月班別、月初區間累計R、月初區間累計R1、1..31、當月R、當月R1、當月指定R休、月底區間累計R、月底區間累計R1、本月班數、萬年班表`。人員列依 ID 排序；M/T 不適用欄位、需求列尚無結果的月統計／月底累計、以及短月份不存在的日期都保留欄位並顯示空白。
- 所有日格顯示 CLI 正規化內容：M 為完整站碼加早／小／夜、T 為早／午／夜、指定休假為中括號格式、X 為起訖時間。Web 不另加 CLI 月表不存在的右側統計欄或底部 Coverage／品質列；Coverage 與規則問題仍由下方警示清單呈現。
- Demand 日格使用具固定高度的下拉選單；上段為空白、R*、早、午／小、夜，下段以群組區隔其他 X 與共同設定的非常態班型。選取一般項目或非常態班型立即儲存；選取其他 X 後輸入時間與說明再儲存。

## 3. 驗證與版本操作

- 每次班表修改由後端直接 M/T 驗證器重算整月。候選有 `SourceRun` 時，跨月驗證固定使用該次求解 immutable input snapshot 中的 previous schedule，包括使用者直接上傳的上月班表；只有沒有求解快照的版本才使用資料庫內上月 `★`。全部硬規則、Coverage 與必要輸入錯誤以紅色呈現；文件已有的軟規則以黃色呈現，不新增未定義業務規則。
- 日格內容不插入警示符號，以免偏離 CLI 格值；違規仍以底色與 title 標示，警示清單另用符號列出規則名稱、繁中原因、員工與日期並可跳至日格，因此不只依賴顏色。
- 紅色錯誤阻擋 `★`；黃色警示不阻擋。同單位同月最多一份 `★`。
- 封存是軟刪除；目前 `★` 必須先改選其他版本，才能封存。

## 4. 上傳、下載與說明

- 第一版只接受 UTF-8（可含 BOM）CSV，最大 5 MB；固定表頭、日期、時間與合法值在選檔前顯示，並提供範本下載。
- Demand 與員工匯入先完整驗證及顯示差異，確認後才在 transaction 寫入；失敗不可部分寫入。previous schedule 與 M 萬年班表也先完整解析才保存 typed 資料。
- 「上月班表」上傳成功後，頁面同時顯示該份上月 `ScheduleVersion` 的「開啟版本」與「標示 ★」。上傳只建立版本，不自動標星；標星仍使用既有唯一 `★`、紅色錯誤阻擋與 AuditLog 規則。
- 直接上傳建立的歷史版本若沒有再前一個月的正式歷史，十一小時只比較已知工作，連續七日一般 R 只檢查版本內已具備完整七日資料的視窗；不得把缺少的上上月日期當成連續工作。若資料庫已有再前一月 `★`，仍須做完整跨月驗證。
- 匯出 CSV 對 `= + - @ tab CR` 起始內容加單引號，避免 spreadsheet formula injection。
- 每個路由頁面右上角都有原生 `<details>/<summary>` `?` 說明，可用 Tab 與 Enter／Space 開關，不依賴 JavaScript；內容說明目的、權限、流程、欄位與常見錯誤。
