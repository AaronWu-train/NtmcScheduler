# 08. 前端功能與互動寬表

本文件定義第一版 Blazor Interactive Server UI。Blazor 元件不直接建立 OR-Tools 模型；所有寫入、驗證與求解均呼叫後端 application service。UI 文字一律繁體中文。

操作流程：需求填寫（可選）→ 建立班表（月份、上月班表、需求寬表、求解）→ 班表列表 → 班表編輯器 → 採用。無審核／發布狀態機。

## 1. 導覽與授權

- 第一層固定為 Dashboard、需求填寫、站務 M、檢修 T、共同設定；Administrator 另見管理功能內的帳號管理與 Log 紀錄。
- 需求填寫進入後以 M／T 分頁切換。站務 M、檢修 T 進入各自工作區後才顯示第二層功能。
- T 第二層為員工資料、建立班表、班表列表；M 另有獨立的萬年班表分頁，承載全域 56 日模板的上傳、預覽、下載與寬表編輯。M 與 T 各自另有「班別時間設定」頁，對應工作區 Editor 可維護早、午、夜班起訖時間。開啟班表編輯器後仍保留目前工作區導覽。
- 「建立班表／求解新班表」只對該工作區 Editor 與 Administrator 顯示並開放；M Editor 在 T 工作區、T Editor 在 M 工作區及純 Viewer 均不可看見或直接開啟該區內容。
- 個別 T 人員能力值只對 T Editor 與 Administrator 顯示；Viewer 與只有 M 編輯權的帳號在員工資料及既有月份快照都不得取得該值。
- 每頁標題下以一句話說明目的；詳細規則放右上角可由鍵盤操作的 `PageHelp`。

## 2. 共同操作規則

- 主要操作置於標題區右上或目前區塊右側；上一步靠左、下一步／儲存靠右；刪除與封存和主要操作分開。
- 按鈕使用「動作＋對象」，例如「新增員工」「上傳上月班表」「開始求解」「採用這份班表」。
- 非同步操作開始時立即顯示「處理中…」並停用所有可能造成重複寫入的操作，以 `finally` 恢復。
- 預期的輸入、權限與樂觀鎖定錯誤使用繁中訊息；非預期錯誤顯示關聯 ID，詳細資料只寫入 Log，不直接顯示 EF／SQL 例外。
- 第一版 CSV 只接受 UTF-8（可含 BOM）且最大 5 MB；員工與需求匯入先完整預覽，確認後才在 transaction 寫入。

## 3. 需求填寫

- 需求填寫由第一層進入，頁內以 M／T 分頁選擇站務或檢修。任何已登入者可選月份與員工填報 R*、當月指定 R休 上限、固定正常班與 X。
- 日格以月曆格狀呈現（週日至週六、依週列），六日與國定假日仍用淺黃底色、56 日區間起點保留垂直分隔線。畫面明示目前登入帳號正在替誰填寫。
- 選取已有填報的員工時載入並可覆蓋；AuditLog 保留操作者與 before／after。
- Demand 需求寬表工具列提供 Editor 專用「匯入員工填報」：先預覽人數、異動與錯誤，確認後一次性覆蓋對應員工的 R休 上限與日格。正式 Demand 須已存在；每月份 Demand 只能匯入一次，完成後顯示時間與操作者。匯入後的新填報仍可保存，但標示晚於本次匯入且不影響 Demand。

## 4. 建立班表

- 建立班表依序為選擇月份、準備上月班表、需求編輯器、執行求解。需求編輯器只指 `demand.csv` 寬表本身，不包含月份、上月班表或求解。
- 上月班表以單一下拉選單選擇資料庫內前一月份尚未封存的版本，或 `（採用上傳班表）`。選取資料庫版本只改變本月求解歷史，不會自動採用該版本。有上月 `★` 時預設使用該版本，沒有時預設切到上傳來源。
- 只有選到上傳來源時才顯示下載範本、上傳、檔名與上傳時間。上傳只保存為該 Demand 的解析快照，不建立上月 `ScheduleVersion`、不可採用。資料庫版本與上傳快照都提供唯讀寬表預覽與 CSV 下載。規則或人力問題只顯示警告，不阻擋求解。
- M 建立班表預設使用全域萬年班表，也可在此步驟上傳只屬於該月份 Demand 的暫用模板；暫用模板不改寫全域內容，可清除後改回全域模板。
- 求解步驟以「最近求解工作」標題區隔工作紀錄；候選的 objective 與違反量明細預設收合。可設定每 seed Time Limit、worker 數與 M seed 數；預設值可直接求解，參數放在「進階求解設定」。
- 成功或 Time Limit 且已有合法候選均顯示「已解出」；Time Limit 另註明「時限到」。沒有合法候選則顯示「未取得合法班表」。已解出的工作以較小字顯示 CLI 同款候選優先層級、總加權分與明細。

## 5. 需求編輯器

- 顯示求解輸入：ID、姓名、所屬、本月新進到職日、T 能力與月班別、月初區間 R／R1、當月日格、當月指定 R休上限及 M 萬年班表代號；尚未求解的月底與結果統計不顯示。
- ID、姓名、所屬皆可升冪／降冪排序，預設 ID 升冪。
- 到職日只用於本月新進員工；到職日前不建立有效日格、不計人力且顯示為不適用。
- 需求中的 `R*` 表示尚待 solver 決定為 R、R1 或 R休。M 正常班以 `1早`、`1小`、`1夜` 等簡寫顯示，T 使用早、午、夜。
- X 下拉選單顯示非常態班型名稱，無名稱才顯示代碼；自行輸入的 X 顯示說明，不以 `X[HH:mm-HH:mm]` 作為 Web 主要文字。CSV 下載與重新匯入時，若該格有名稱或說明，使用 `X[HH:mm-HH:mm|註記]` 保留。

## 6. Dashboard 與班表列表

- Dashboard 即時顯示最近 5 筆求解工作，包括排隊、執行、成功、Time Limit、無解與失敗。
- 求解完成後都是一般班表版本；M 班表列表的歷史匯入亦然。所有未封存版本使用同一個班表編輯器並可自由修改。
- 同月份可永久保存多份班表，最多一份採用班表，也可暫時沒有採用班表；UI 使用「採用」「取消採用」「已採用」，不以單獨星號表示業務狀態。未封存班表可直接修改名稱。M 班表列表可先指定月份再上傳歷史班表，每次建立新的 `Imported` 版本，不覆蓋或自動採用同月既有版本。
- 班表列表顯示求解版本的最佳化分數：M 顯示 J1、J4；T 顯示 J1–J5。沒有求解來源的上傳或舊版班表顯示 `—`。列表上的「建議 N 項」對應班表編輯器「檢查結果」中的改善方向。

## 7. 班表編輯器

- 左側固定 ID、姓名與所屬；本月新進者在姓名旁顯示到職日。ID、姓名與所屬皆可排序。
- 中間只顯示實際月份日期。六、日與國定假日整欄使用淺黃色；每個落在月份內的 56 日區間起點以明顯垂直線分隔。
- 日格採緊湊文字：R／R1／R休／`R*`／`R1*`／`R休*` 為深紅粗體；早班為一般黑字；M 小班與 T 午班為黑字加底線；夜班為黑色粗體；X 為藍字加淺藍底。
- M 日格使用 `1早` 等簡寫；M CSV 下載亦以站號簡寫輸出正常班。X 顯示名稱、代碼或自行輸入說明，開始與結束時間在編輯視窗查看；若匯出 CSV，則以 `X[HH:mm-HH:mm|註記]` round-trip 保留同一註記。
- 班表與需求／上月 CSV 下載依工作區省略欄位：M 移除「能力」與「T月班別」；T 移除「萬年班表」。T 員工匯入範本仍保留能力欄。
- 右側先依本月相交的每個 56 日區間顯示 R 目前／16、R1 目前／應有數，再顯示本月 R、R1、R休、早、小／午、夜、X 與總班數。`R*`、`R1*`、`R休*` 分別計入實際 R、R1、R休；R休不計入 16R 或 R1 額度。
- M 表格底部依車站顯示每日早／小／夜需求、內部安排、外派人數與合計；Coverage 差額直接在統計列呈現。T 顯示每日各班組的出勤、專業與能力摘要。
- 表格不設會遮住最後資料列的固定高度；水平捲軸位於底部統計之後並保留間距。

## 8. 規則與採用狀態

- 紅色只代表勞基法相關的「相鄰工作不足十一小時」與「連續七日至少一日一般 R」。相關日格使用紅色邊框與非純色的警示符號。
- 其他 hard rule 與 Coverage 仍阻擋採用，但不使用勞基法紅色。黃色軟規則警示不阻擋採用。
- M 班位 Coverage 差額與 R休 非指定日期不列入「檢查結果」；Coverage 差額仍在底部統計列呈現。
- 不顯示常駐的大型規則警示卡；未能直接落在區間、月統計或 Coverage 的問題收在預設關閉的「檢查結果」。
- 「檢查結果」的軟目標建議應列出可定位的位置：可歸屬到員工日格者可點選並捲動至該格；班別人力與公平性等群組指標則列出相關日期或人員，不能誤示為單一日格錯誤。硬規則訊息與軟目標建議明確區分。
- 採用後顯示黃色「已採用」狀態；目前採用班表可取消採用，或改採用其他版本後再封存。

## 9. Log 紀錄

- Log 紀錄列表欄位為：時間、帳號、登入工作階段、來源 IP／裝置、工作區、繁中動作、操作對象、異動內容、結果；完整帳號 ID、SessionId、關聯 ID、User-Agent、ResourceType／Id 與原始 before／after JSON 收在可展開的技術詳情。
- 篩選支援起迄日、工作區、繁中動作（查詢仍用英文 Action 值）、帳號、SessionId、IP；可由任一異動篩出同一登入工作階段的登入、修改、下載與登出軌跡。
